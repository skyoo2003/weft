## [v0.1.0](https://github.com/skyoo2003/weft/releases/tag/v0.1.0) - 2026-09-06

### Exported API

- Baseline: the surface at this tag is whatever `pkg/engine/testdata/engine_api.txt` and `public_api.txt` record at the tagged commit, and every later release states its diff against them rather than restating the whole surface. ([#9](https://github.com/skyoo2003/weft/issues/9))
- Three additions, no changes: `Scrub(dir)` verifies every byte of a committed index, which `Open` no longer does; `Index.Close` releases an opened index's mappings; `Index.Merge` collapses the oldest segments once the count passes eight. The six read methods a scorer calls are untouched. ([#9](https://github.com/skyoo2003/weft/issues/9))
- `engine.Index.Nearest(v []float32, k int) []DocID` returns the DocIDs worth scoring exactly for a query vector — ascending, free of repeats, wider than the answer, and carrying no score of its own, because the metric stays with the caller (D-008). It is not a promise that the exact top k are among them; `docs/EVAL.md` §5.14 publishes the measured recall against a brute-force scan. ([#11](https://github.com/skyoo2003/weft/issues/11))
- `engine.Index.Vector(DocID) ([]float32, bool)` returns a document's vector without materialising the rest of it: scoring 64 documents allocated 13,312 bytes against `Doc`'s 4,208,024. The checksum guarantees `Doc` gives all hold, a document with no vector answers false, and D-015 records the two routes not taken. ([#14](https://github.com/skyoo2003/weft/issues/14))
- `Index.Commit` takes a `context.Context` first — `Commit(ctx, dir)` — so every caller has to be edited, and no `CommitContext` twin exists because v0.1.0 is not cut and there is no compatibility to keep. Cancelling before the manifest rename publishes nothing; cancelling after it is ignored, because the commit has succeeded, and `Merge` is still uncancellable (D-017). ([#16](https://github.com/skyoo2003/weft/issues/16))
- Three lines: `Index.Delete(string) bool`, `Index.Update(Document) (DocID, error)` and `ErrNoSuchKey` — `Update` keeps a pending document's id, spends a fresh one for a committed document, and refuses a key no live document holds rather than inserting. `Len` now means one past the highest assigned `DocID` rather than the document count, and `Stats` is the live population. ([#17](https://github.com/skyoo2003/weft/issues/17))
- `engine.New` and `engine.Open` take `...Option`, adding `Option`, `Tokenizer`, `WithTokenizer`, `Index.Tokenize` and `ErrTokenizerMismatch` with all 77 existing call sites still compiling. The one thing to act on: `Open` returns `ErrTokenizerMismatch` when the directory was split by a different tokenizer, so pass the `WithTokenizer` the commit was made with — format v4, unchanged. ([#19](https://github.com/skyoo2003/weft/issues/19))
- `engine.Index.Neighbors(id) ([]DocID, bool)` resolves a document's `Links` into DocIDs under one read lock, dangling and deleted keys dropped, with the bool separating a leaf from a missing document. `public_api.txt` also gains the `scorer/graph` additions; nothing already written stops compiling and the format is v4, unchanged. ([#21](https://github.com/skyoo2003/weft/issues/21))
- `engine.Index.Terms(prefix, limit) []string` returns the indexed terms starting with a prefix — sorted and then truncated, so which terms a limit cuts does not depend on map iteration order. It is the read a term pattern needs and `Lookup` cannot serve; nothing already written stops compiling and the format is v4, unchanged. ([#22](https://github.com/skyoo2003/weft/issues/22))
- `engine.Index.PostingBound(term) int` gives an upper bound on how many postings `Lookup` would return without decoding any of them: one varint per segment, tight to within one block per segment. It is a bound and not a document frequency — it does not subtract tombstones — and the format is v4, unchanged. ([#23](https://github.com/skyoo2003/weft/issues/23))
- **`engine.Document` gains a sixth field, so an unkeyed composite literal stops compiling** — the one break, alongside additions `Field`, `Document.Fields`, `FieldTerm`, `ErrBadField` and `text.NewField`. `DocLen` and `AvgDocLen` now count every field's tokens, so adding a field to an existing corpus changes BM25 scores for those documents. ([#24](https://github.com/skyoo2003/weft/issues/24))
- **`query.Glob` takes a field as its second argument**, so `query.Glob(ix, "go*")` becomes `query.Glob(ix, "", "go*")` — the one break, taken rather than wrapped so no call site spells the field separator itself. Added: `Range`, `Fuzzy`, `EncodeInt`, `EncodeTime` and `MaxEditDistance`, all reading the term dictionary `Open` already decodes, so the format is v5, unchanged. ([#25](https://github.com/skyoo2003/weft/issues/25))
- `query.Parse(ix, string) (Plan, error)`, `Plan.Scorers` and `Plan.Fuse(engine.Fuser) engine.Fuser` are added, and nothing already written stops compiling. `Scorers` is exported while the constraint indexes are not, so reordering the list after parsing invalidates them — which is why `Fuse` is a method rather than a free function. ([#26](https://github.com/skyoo2003/weft/issues/26))
- `engine.BlockCursor` walks one term's postings a block at a time and `engine.Collector` keeps the best k of a stream in memory bounded by k, so a scorer can stream rather than accumulate. **`Index.PostingBound` is replaced by `Index.PostingCount`**, which is exact and subtracts tombstones — a correction, not a rename, because an IDF computed from a bound drifts every score in the corpus. ([#29](https://github.com/skyoo2003/weft/issues/29))

### On-disk format

- Version 1, described in `docs/FORMAT.md`. Nothing to migrate from — this is the first tag. ([#9](https://github.com/skyoo2003/weft/issues/9))
- Version 2 adds `docoff` and `keys`, so a DocID or a Key reaches its document without decoding what is in front of it, plus per-unit checksums and `(name, base, count)` on every manifest segment entry. Version 1 indexes are refused with `ErrBadVersion` and are not migrated, an argument available exactly once (D-007). ([#9](https://github.com/skyoo2003/weft/issues/9))
- Version 3 adds one section, `ivf`, holding an IVF-flat partition of a segment's vectors with each inverted list sealed by a CRC-32C seeded with its own list number. Version 2 is read without conversion — a v2 segment reports no partition and offers every id it holds — and `Index.Merge` upgrades it as a side effect of maintenance the index already performs. ([#11](https://github.com/skyoo2003/weft/issues/11))
- Version 4 adds `dead-<gen>`, the whole tombstone set as ascending DocID deltas, sitting beside `MANIFEST` because a commit that only deletes publishes no segment. Version 2 and 3 directories are read without conversion; the bump exists so a build predating tombstones refuses the directory rather than answering with every deleted document still in it. ([#17](https://github.com/skyoo2003/weft/issues/17))
- **Version 5** appends a field block to each `docs` record and adds no section, so v2 through v5 are all read and a v4 record is a v5 record with the count absent. `docs/FORMAT.md` §7.9 records what it cost and the rule it leaves behind: append to a section, not to a record, unless the field belongs to the record's identity. ([#24](https://github.com/skyoo2003/weft/issues/24))

### Minimum Go

- 1.26 — the floor, not a tested ceiling: newer is untested rather than unsupported, and the gate pins this one line rather than a matrix. ([#9](https://github.com/skyoo2003/weft/issues/9))

### Added

- `weft-eval recall` and `make recall` measure what nDCG cannot see about an approximate vector index: overlap with a brute-force scan, candidates scored per query, latency both ways, and the working set in bytes and distinct pages. A partition losing half the true neighbours holds nDCG steady when those neighbours were unjudged, which on 50 queries against 171,332 documents is most of them. ([#11](https://github.com/skyoo2003/weft/issues/11))
- `weft-eval bench` and `make bench` publish a latency distribution rather than a mean: an open-loop arrival ladder from 12.5% to 200% of measured sequential throughput, each request timed from its intended send time, reporting p50/p95/p99/p99.9 with and without stop-the-world time. A quantile without 100 samples beyond it is left out, and which rung the headline is quoted at was fixed before the numbers existed. ([#12](https://github.com/skyoo2003/weft/issues/12))
- `docs/PERF.md` publishes the first latency distribution this project has had: weft's p99 on the 171,332-document corpus is 98.041ms at the registered load point, against bleve v2.6.0's 47.123ms on the same machine, corpus, query set and arm — 2.08x. The comparison lives in `bench/`, a separate module, so `go list -m all` still prints one line. ([#12](https://github.com/skyoo2003/weft/issues/12))
- `weft-eval bench -writes` prices what a commit costs the reads running against it: a commit adding 20,000 documents holds the lock 11.641s and the worst read caught in it waits 13.142s, while a commit below the partition floor costs 36ms. It copies the index first, because committing into the published corpus would rewrite the thing every measured number names. ([#12](https://github.com/skyoo2003/weft/issues/12))
- `weft-eval bench -rates 3.21,6.42,12.84,25.67` runs the rates you name instead of the sweep `-rate 0` derives, because a derived sweep confounds a rung's result with the ladder that produced it. A named ladder gets no saturation point and no headline, and every entry is bounds-checked at flag time rather than ninety minutes in. ([#14](https://github.com/skyoo2003/weft/issues/14))
- `weft-eval bench` prints what one query allocated on each rung — KiB and allocation count per query — which is the attribution `ru_maxrss` cannot give, since a high-water mark the kernel never lowers says only how much a rung raised the process mark. Shed requests are out of the denominator, and a rung with no samples omits the line rather than printing a zero that reads as a measurement. ([#15](https://github.com/skyoo2003/weft/issues/15))
- `Index.LookupInto(term, buf)` is `Lookup` writing into a buffer you own, so a caller walking several terms holds the longest posting list instead of their sum — 53.2% of what a query allocated, and `pkg/scorer/text` now reuses one buffer: 10,869.0 KiB per query against 15,691.3, nDCG@10 identical to four decimals. The answer does not change; the result is yours to modify, and yours only until the next call with the same buffer. ([#15](https://github.com/skyoo2003/weft/issues/15))
- `Index.Delete(key)` and `Index.Update(doc)` mean a corpus that changes no longer means a full re-index, with the tombstone check inside `engine`'s read path so no scorer mentions deletion and `pkg/fusion` is unchanged. Nothing is reclaimed: a deleted document keeps its bytes and every `Merge` copies them forward, because renumbering would move rankings (D-019). ([#17](https://github.com/skyoo2003/weft/issues/17))
- `engine.WithTokenizer(tok)` replaces the tokenizer at index time and query time together, so there is one function value per index and no way to configure the two sides apart. It is what lets a Korean query find a corpus the default tokenizer splits wrongly — `ExampleWithTokenizer` is a ten-line character-bigram tokenizer — and there is deliberately no `SetTokenizer`, since calling one after the first `Add` would leave a corpus in two term spaces (D-022). ([#19](https://github.com/skyoo2003/weft/issues/19))
- **The citation graph is now an index rather than a walk over documents**: `graph.NewAdjacency` resolves every document's links into DocID space forward and reverse, and `graph.NewPPR` ranks on it by Andersen–Chung–Lang forward push, bounded by `1/(restart × precision)` however large the corpus. On 20,000 documents with 120,000 edges the graph arm goes from 1.379 ms and 48,522 allocations a query to 236 µs and 230; whether it improves nDCG is not claimed. ([#21](https://github.com/skyoo2003/weft/issues/21))
- **`pkg/query` — the constraints rank fusion does not express on its own.** `Must` and `MustNot` read a stream as a restriction rather than a vote and compose with each other, `Glob` and `Phrase` return every match rather than truncating to k so they can be used as one, and a stream index past the end of the list drops everything, because a constraint that cannot be evaluated is not satisfied. ([#22](https://github.com/skyoo2003/weft/issues/22))
- **`weftd` now speaks most of the OpenSearch query DSL and refuses the rest by name** — eleven leaf clause kinds plus `bool` and paging, mapped onto `pkg/query` with zero lines changed under `pkg/`, alongside five field mapping types and an NDJSON `_bulk` that refuses a batch whose action and source lines are off by one. The refusal rate is counted rather than claimed, 8 of 25 documented rows, and `TestTheRefusalRateIsCounted` fails in both directions. ([#25](https://github.com/skyoo2003/weft/issues/25))
- **Hybrid search over HTTP**: `knn` becomes a `scorer/vector` stream, `hybrid` fuses any number of sub-queries, weft's own `weights` array becomes `fusion.FuseWeighted` by position, and a decay function becomes a `scorer/recency` stream, while `search_pipeline` and the decay's parameters are refused with a 400 that says why. Adding that fourth signal changed 0 lines of fusion code and 57 in its query clause; the 27 lines over budget are the wire having no place to say which date is the document's time. ([#26](https://github.com/skyoo2003/weft/issues/26))
- **The load ladder can be aimed through a socket**: `weft-eval bench -http 127.0.0.1:9200` drives a running `weftd` with the same open loop, rung structure, saturation rule and suspension tolerance, and `make bench-http` starts the server, runs the ladder and stops it. The memory column comes from the server's own `GET /_nodes/stats` rather than the load generator's counters, and a failed read ends the run rather than falling back to numbers about the wrong program. ([#27](https://github.com/skyoo2003/weft/issues/27))
- **A query string syntax**: `query.Parse(ix, "+title:covid -draft \"airborne transmission\"")` returns a `Plan` the caller assembles into a `Search`, covering bare terms, `field:term`, `+`/`-`, phrases, `term*`, `term~2` and `field:[lo TO hi]`. There is no boolean algebra, because a flat clause list is exactly what rank fusion expresses; an unterminated quote or an inverted range is an error rather than a query that quietly returns nothing. ([#26](https://github.com/skyoo2003/weft/issues/26))
- **`make bench-head` — a head-to-head against bleve that runs in under a minute**, asking how much work each engine does for one query, sequentially, on a corpus it generates rather than the prepared index `make bench` needs and has come back void on three rounds running. It is not a tail, a throughput figure or a quality comparison: bleve stems and removes stopwords where weft's default tokenizer does neither. ([#28](https://github.com/skyoo2003/weft/issues/28))
- **weftd now has a surface of its own**: `POST /{index}/_weft/search` takes a request that is a stream list, with positional weights, a fusion `depth` separate from `size`, and a per-hit breakdown of where each stream ranked a document before fusion — three things the OpenSearch DSL has no way to say. It is not a second parser: a stream compiles through the same function `_search` uses, `pkg/` changed zero lines, and `opensearch-py` 3.2.0 still drives weftd unmodified. ([#28](https://github.com/skyoo2003/weft/issues/28))
- weftd carries the graph signal: a mapping binds a keyword field with `"links": true`, because the wire cannot tell an array of strings from an array of document ids, and the `weft_graph` clause reaches the rest of `pkg/scorer/graph` from `seeds`. Nine more routes reach the half of engine a search never touches — `_flush`, `_refresh`, `_forcemerge`, `_count`, `_analyze` and four under `/_weft/` — with `pkg/` changed 0 lines. ([#26](https://github.com/skyoo2003/weft/issues/26))
- **weft speaks gRPC, and it cost the root module nothing**: `grpc/` is a second module, so `go list -m all` still prints one line, and `weftg` serves what `POST /{index}/_weft/search` serves — search only, because one writer per index is an invariant two processes over one directory would both violate. The service decides nothing: every method is conversion either side of one call into `opensearch.NativeSearch`, and a request field on one wire without a counterpart on the other fails the build. ([#28](https://github.com/skyoo2003/weft/issues/28))

### Changed

- `Open` maps segments instead of decoding them, so opening an index costs the vocabulary rather than the corpus — 54 ms against 979 ms on 171,332 documents — and `Commit` writes only what was added since the last one, 245 bytes after one `Add` on a 7.2 MB corpus. Whole-file verification moved from `Open` into `Scrub`, so damage in bytes no decoder reaches now needs `Scrub` to find. ([#9](https://github.com/skyoo2003/weft/issues/9))
- `scorer/vector` no longer scans the whole corpus: it reads `engine.Index.Nearest`, scoring 30,549 of 171,332 documents per query and returning 4.6 times faster. The consequence a caller has to know is that vector results are now approximate — recall@10 against an exact scan is 0.992 and text+vector nDCG@10 moved 0.6233 to 0.6211 — while nothing about the scorer's contract changed. ([#11](https://github.com/skyoo2003/weft/issues/11))
- `cmd/weft` fuses the graph stream at a tenth of a vote instead of a full one, so the demo now agrees with the advice the rest of the project gives about that scorer, and the rankings it prints change. No exported API moved: the weights index by stream position, so fusion still does not learn what a graph scorer is. ([#13](https://github.com/skyoo2003/weft/issues/13))
- `weft-eval bench` and the bleve comparison refuse to publish figures they did not measure: past a five-second tolerance a rung prints SUSPENDED and the summary refuses the run, because a ladder measured across thirteen hours of clamshell sleep had reported every rung finishing exactly on schedule. A ladder cut short no longer prints a saturation point or a headline either, so an interrupted sweep is no longer indistinguishable from a complete shorter one. ([#14](https://github.com/skyoo2003/weft/issues/14))
- Every rung of `weft-eval bench` now says how much *it* raised the process's peak resident set, or that it raised nothing and the figure beside it therefore belongs to an earlier rung. `ru_maxrss` is a high-water mark with no reset, and a pass line was once judged against 345.2 MiB reached two rungs earlier at half the rate; no published figure moves. ([#14](https://github.com/skyoo2003/weft/issues/14))
- `weft` with no arguments prints the help instead of starting an interactive demo over a corpus compiled into the binary. That demo is three examples now, one case each: `examples/breakdown` prints what fusion did, `examples/weights` runs one query under two fusers, and `examples/sparse` is about the documents a scorer cannot see. ([#26](https://github.com/skyoo2003/weft/issues/26))

### Fixed

- Five defects in the milestone 5 load instrument, all found by review and all biased toward a flattering number: GC pause charged over a shorter window than the latency it is subtracted from, `-writes` stamping its commit window after the `Add` loop, a 50-sample unloaded median where the rule wants 200, `GCPauseTotal` allocating ~150 MiB per ladder, and GC CPU share taken from since-start totals. Every published figure was re-measured: the headline p99 moved 98.041ms to 108.193ms. ([#12](https://github.com/skyoo2003/weft/issues/12))
- A commit no longer stops reads: the worst read due inside a commit window waits **61 ms** where it waited 13.072 s, 214× better and below the 191 ms worst read outside the window. `Commit` encodes the segment under a read lock and takes the exclusive one only for the manifest swap, with a second mutex serialising `Add`, `Close`, `Merge` and `Commit`; the 11.3 s window itself did not move and `Merge` is unchanged. ([#16](https://github.com/skyoo2003/weft/issues/16))
- `Scrub` no longer calls a re-added-then-deleted key damage: `scrubDocs` kept the first record for such a key where the keys entry names the last, so `Add`, `Delete`, `Add`, `Commit`, `Delete`, `Commit`, `Scrub` reported `ErrCorrupt` on a healthy index. Also on that path, the running total of deleted tokens was an `int` against a `uint64` collection total, so a 32-bit build past 2^31 deleted tokens turned BM25's length normalization off silently. ([#18](https://github.com/skyoo2003/weft/issues/18))
- **`scorer/text` allocated a corpus-sized map on every query, including queries that matched nothing** — 4.73 MB a query on the evaluation index, a floor scaling with the corpus rather than with what the query reached. It is now sized from `Index.PostingBound`: a query matching nothing goes from 78,685 ns and 1,182,240 B to 151 ns and 16 B, with no score or ranking change. ([#23](https://github.com/skyoo2003/weft/issues/23))
- **`engine.TopK` sorted every candidate to return ten of them**, so a query for a term held by all 50,000 documents paid a full n·log n sort for the 49,990 it discarded. It now selects with a k-sized heap over `cands[:k]`: `BenchmarkTopK` at k=10 goes from 3,956 µs to 168 µs with zero allocations, `scorer/text` end to end from 5,871 µs to 2,112 µs, and the answer is identical because the comparator is a total order. ([#27](https://github.com/skyoo2003/weft/issues/27))
- **`scorer/text` scored term-at-a-time and held three corpus-sized structures to do it**, which is why milestone 22 measured it allocating 156× bleve on the widest query. It now walks document-at-a-time over one `engine.BlockCursor` per term into a k-sized `engine.Collector`: on 50,000 documents 2,819,333 B and 2,139,639 ns become 32,337 B and 944,509 ns, against bleve it is 3.1× faster at 1.8× the memory, and no score or ranking changes. ([#29](https://github.com/skyoo2003/weft/issues/29))

### Security

- `Commit` creates its index and segment directories with mode 0o700 rather than 0o755. The corpus is the caller's data and nothing weft does needs another user on the machine to read it — including the caller's own group, which 0o750 would let read the 0o644 segment files inside. ([#9](https://github.com/skyoo2003/weft/issues/9))
- CodeQL runs on every Go change and once a week, and `SECURITY.md` now names both automated gates rather than only the fuzz one: it is the half of the decoder question fuzzing cannot reach, finding where a length the file chose ends up at an allocation. It is not in `make all`, because building a dataflow database takes minutes, so its findings land on the Security tab rather than in a pull request check. ([#23](https://github.com/skyoo2003/weft/issues/23))

### Documentation

- A published latency figure has been measured twice and come back: the same arrival rate gave 37.9 ms once and 1.539 s twice, because what a repetition must hold constant is the ladder in front of it and its depth — reached as the fourth rung of a full-depth ladder, the rate returned within 0.07% of its first observation. The repaired procedure is `docs/PERF.md` §3 rule 3 and D-013; no figure already published has been re-measured under it, and each remains labelled a single observation. ([#14](https://github.com/skyoo2003/weft/issues/14))
- A constraint expressed as a scorer does not filter, and the documentation now says so: rank fusion is a union of votes, so everything a scorer refuses comes back on another scorer's vote, and what excludes is a `Fuser` reading one stream as a restriction — `engine.Fuser`, `ExampleFuser` and the README carry it. Three further silences are closed, and all four defects were found by two blind trial subjects who opened no source file and needed no new exported name. ([#18](https://github.com/skyoo2003/weft/issues/18))
- Two questions the PRD left open are now answered where they can be read: D-022 prices the four places the tokenizer seam could have attached and why three were rejected, and D-023 does the same for the mismatch check, including the third check that was written and taken back out. `FORMAT.md` §8 publishes the four ceilings that leaves, and README, ADOPTION and `bench/README.md` carry the rows that follow. ([#19](https://github.com/skyoo2003/weft/issues/19))
- README is 91 lines from 261, and the detail it carried now lives in four documents that each answer one question: `docs/STATUS.md`, `docs/LIMITATIONS.md`, `docs/ARCHITECTURE.md` and `docs/SCORERS.md`. Every inbound link moved with the text, the full make target reference is now generated from the Makefile into CONTRIBUTING, and three stale claims died on the way. ([#23](https://github.com/skyoo2003/weft/issues/23))
- CONTRIBUTING's make target reference caught up with the Makefile it is generated from: seven targets the last three milestones added were missing entirely — `serve`, `serve-grpc`, `compat`, `compat-grpc`, `grpc-build`, `bench-preflight` and `bench-http`. Three claims had gone stale rather than absent: four CI checks outside `make all` and not three, five fuzz targets across two packages and not two, and `make lint` reaching `grpc/` as well as `bench/`. ([#29](https://github.com/skyoo2003/weft/issues/29))
